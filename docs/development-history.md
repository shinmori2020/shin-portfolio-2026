## 履歴から読み取れる作法

このリポジトリで作業を継ぐ際に守るべき癖。

- **原因を突き止めてから直す。** `root-cause the ...` という書き方が複数ある。対症療法で閉じず、原因が分かったら docs に残す。原因の説明が間違っていたと後で気づいたら `fdb54b0` のように訂正コミットを打つ。
- **踏んだ罠は必ずドキュメント化する。** `docs/works-capture.md`（撮影）と `docs/view-transitions.md`（共有要素遷移）が実例。
- **handoff フォルダは統合したら削除する。** `de42a88` で contact-animation-handoff を削除済み。`finishing-package/` に 04-microcopy だけ残っているのは、それが唯一の未消化分だから。
- **revert より上書き。** 方針転換は revert ではなく次のコミットで作り直す形が多い（`1552d1a` → `00bc0a2` など）。revert は1件のみ。
- **却下した演出を蒸し返さない。** タイプライター表示・ホバーの浮き上がり・数値実績バンドは、一度実装して意図的に捨てている。
- **コミットメッセージ** は初期〜中期が英語、7/11 以降が日本語。prefix は `feat` / `fix` / `style` / `copy` / `content` / `perf` / `docs` / `chore` / `tweak` / `refine` / `revert` / `test` を使い分ける。**継続する場合は7月以降の日本語スタイルに合わせる。**
